# TokenFurnace v0.1.0



零依赖的本地 Web 控制台，用来消耗、观测和按额度管理 LLM 的 token 用量。



## 下载哪个文件



**① `tokenfurnace-0.1.0-windows.zip`（推荐）**



解压后双击 `start.bat`（Windows）或运行 `start.sh`（macOS / Linux）。包里是 `.pyz` 加两个启动脚本，脚本会自己找 Python，找不到会告诉你去哪装。



**② `tokenfurnace-0.1.0.pyz`（单文件）**



整个工具就这一个文件，在终端里跑：



```bash

python tokenfurnace-0.1.0.pyz

```



浏览器会自动打开 `http://127.0.0.1:8760/`。需要 Python 3.9+，没有其他依赖，不用 clone、不用 pip。



`.pyz` 是 Python 的 zipapp（PEP 441），把一个完整程序打成一个文件，等同于 Java 的 `.jar`。**它要在终端里用 `python` 运行，双击通常没反应**——Windows 默认没给 `.pyz` 关联打开方式，所以才另做了上面那个 zip。



**③ `Source code`（zip / tar.gz）**



源码，只在你想读代码或参与开发时才需要。



配置和账本会落在你运行命令时所在的目录（`config.json` 和 `data/`）。



### 校验和



构建是**可复现的**：同一份源码在任何机器、任何时刻构建出来的字节完全一致。下载后可以自己核对：



```

tokenfurnace-0.1.0.pyz          62608560aa11bf60438486099bef489d0ce9ea5963e1c16e7fb328cb2c4b94a2

tokenfurnace-0.1.0-windows.zip  8096793bbb876f07c5d7784760b4c3ab463b91c88d35ba5408d52d358e2ce6fd

```



```bash

# Windows

certutil -hashfile tokenfurnace-0.1.0-windows.zip SHA256

# macOS / Linux

shasum -a 256 tokenfurnace-0.1.0-windows.zip

```



想自己重建对比也行：`python scripts/build_release.py`



## 这个版本有什么



- **四种接口协议**：Anthropic Messages、OpenAI Chat、OpenAI Responses、Gemini Native。

  适配层处理路径、认证头、系统提示位置、输入字段、输出上限和用量字段的差异

- **多配置并发**：一次勾选多个配置批量启动，每个会话用各自的密钥、模型和额度

- **积分池**：平台把积分拆成多个独立计额的池时（比如专属池 + 通用池），逐池声明即可。
  专属池用尽时平台会**静默**改扣下一个池、请求照样返回 200，工具察觉不到；
  按池核算后，某个池用满就停手，不会误烧别的池
- **滚动窗口记账**：5 小时和 7 天两个滑动窗口，积分逐请求落库，撞墙精确等待而不是轮询
- **返赠统计**：池配置可填返赠比例（比如「消耗 1 专属积分返 1 通用积分」），
  窗口面板会显示本窗口和周累计的预计返赠，用来核对平台到底给没给
- **重算历史**：换算系数填错后修正时，可把历史记录按新系数重新折算，
  不用等 7 天让错误的窗口数据自然过期

- **四维预算刹车**：积分、token、请求数、时长，任一触顶即停

- **错误四分类**：按响应体 `message` 而不是 `type` 判断，避免把每秒请求数限流误判成额度耗尽

- **退避分级**：`rps` / `server` 让整个会话一起等，`timeout` / `network` 只停当前线程

- **自适应**：超时按实测延迟调整，即时速率窗口按完成密度自动放宽

- **持久化**：SQLite 记账，可导出 CSV，历史会话按模型和错误拆分



## 验证方式



想自己确认四种协议确实不同，不用接真实服务：



```bash

python scripts/protocol_probe.py

```



它起一个本地 mock 端点，把每种协议真实发出的 HTTP 请求抓下来打印。四种协议会产生四个不同的路径、四种不同的请求体、四种不同的用量解析。



## 已知限制



- **停止会话时在途请求无法中断**。urllib 阻塞在 `recv` 上，Python 也没法强杀线程，所以状态会显示「正在停止」而不是假装已经停了。这些请求完成后仍会被正确记账

- **本地账本只记一个合并口径**。如果平台把积分分成多个池（比如通用积分和专属积分）各自独立计额，本地窗口占用和平台真实口径会在混用模型时对不上，需要自己留余量

- 默认只绑 `127.0.0.1`。`--host 0.0.0.0` 不带任何鉴权，要远程访问请自己套反向代理
